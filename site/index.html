Staticly

Host a static site on Fastly using Object Storage and a VCL service.

GitHub

Overview

This guide walks through hosting a static site entirely on Fastly's network using Fastly Object Storage as the origin and a VCL CDN service to serve content at the edge. No external hosting provider or cloud storage account is needed.

All code, scripts, and VCL lives in the GitHub repository.

  • Fastly-native Everything on Fastly's network, no external origin
  • Edge-cached Content cached globally after first request
  • Shielded Single POP talks to origin, reducing storage load
  • S3-compatible Upload with curl, AWS CLI, or any S3 tool
  • Secure credentials Stored in a private Edge Dictionary
  • Simple deploy One script to build, one to deploy

Prerequisites

  • A Fastly account with Object Storage enabled
  • The Fastly CLI installed and authenticated (fastly auth login)
  • curl ≥ 7.75 (for --aws-sigv4 support)
  • jq for JSON parsing in the setup script

Quick Start

scripts/setup.sh automates the entire setup — Object Storage bucket, Fastly service, Edge Dictionary, backend, and VCL snippets — in one command: 

./scripts/setup.sh <service-name> <domain> <bucket-name> <region>

Setup saves credentials to .env (gitignored). Then build and deploy: 

./scripts/build.sh
./scripts/deploy.sh

The rest of this guide explains what those scripts do and why.

What the Setup Does

The setup script performs these steps via the Fastly CLI and curl — no control panel needed:

Create Object Storage Access Keys

Access keys authenticate requests to Object Storage via the S3-compatible API. The script creates a key pair using the Fastly CLI.

Important The secret key is only shown once at creation time. The setup script prints it at the end — save it securely.

Create an Object Storage Bucket

The Fastly CLI doesn't have a bucket creation command, so the script calls the S3-compatible CreateBucket API directly via curl --aws-sigv4. Bucket name and region are provided as arguments.

Create a Fastly VCL Service

A standard CDN service is created with a domain and the Object Storage regional endpoint as the backend origin, using TLS with the correct SNI and certificate hostname settings.

The backend is configured with a shield POP close to the Object Storage region. Shielding designates a single Fastly POP as the sole point of contact with the origin — all other POPs fetch from the shield rather than going to Object Storage directly. This collapses many parallel cache misses into fewer origin requests, improving cache hit ratio and reducing load on the storage backend.

The setup script automatically selects the best shield POP based on the Object Storage region (e.g. iad-va-us for us-east, amsterdam-nl for eu-central).

Create a Private Edge Dictionary

Edge Dictionaries are versionless key-value stores accessible from VCL at runtime. A private (write-only) dictionary is created and populated with the access key, secret key, bucket name, and region.

Using a private dictionary means:

  • Credentials stay out of VCL source and version history
  • They can be rotated without creating a new service version
  • The API won't return the values when the dictionary is listed
Note Private dictionaries are stored in plain text on Fastly's infrastructure — not encrypted like Secret Stores (Compute only). For VCL services, they are the best available option.

Add VCL Snippets

Five VCL snippets handle request routing, authentication, errors, and caching:

vcl/recv.vcl runs in vcl_recv. Strips query strings (static sites don't use them), redirects extensionless paths to add a trailing slash, and appends index.html to directory paths.

vcl/miss.vcl runs in vcl_miss. On a cache miss at the shield it reads credentials from the Edge Dictionary, constructs an AWS SigV4 Authorization header, prepends the bucket name to the path, and sends the signed request to Object Storage. Handles both GET and HEAD requests.

vcl/fetch.vcl runs in vcl_fetch. Intercepts 403/404 responses from Object Storage and triggers a custom error page.

vcl/error.vcl runs in vcl_error. Generates 301 redirects for the trailing-slash rewrite and returns a styled 404 page when files are not found in Object Storage.

vcl/deliver.vcl runs in vcl_deliver. Sets Cache-Control headers: HTML is revalidated on every request, while static assets (CSS, images, fonts) are cached for one year with immutable.

Activate the Service

The service version is activated, making it live on Fastly's edge network.

Build and Deploy

With the service set up, deploying content is two steps:

Build

scripts/build.sh copies site/ into dist/ for deployment. This is intentionally simple — it's where you would add minification, asset processing, or other build steps.

Deploy

scripts/deploy.sh uploads each file in dist/ to Object Storage using curl --aws-sigv4, setting the Content-Type header based on file extension. The Content-Type set during upload is what Object Storage stores and returns on GET.

CI/CD

A GitHub Actions workflow automatically builds, deploys, and purges the cache when changes to site/ are pushed to main. It requires five repository secrets:

  • FOS_ACCESS_KEY and FOS_SECRET_KEY — Object Storage credentials
  • FOS_BUCKET and FOS_REGION — bucket name and region
  • FASTLY_API_TOKEN — a Fastly API token for cache purging

Request Flow

  1. Client requests https://example.com/
  2. Fastly runs vcl_recv, rewrites / to /index.html
  3. On a cache miss at the edge POP, the request is forwarded to the shield POP
  4. On a shield miss, vcl_miss reads credentials from the Edge Dictionary
  5. VCL constructs an AWS SigV4 Authorization header
  6. The bucket name is prepended: /index.html becomes /my-bucket/index.html
  7. The shield sends the signed request to Object Storage
  8. Object Storage returns the file; the shield caches it, the edge POP caches it, and the client is served

Limitations

  • MIME type mapping is manual. Uncommon file types default to application/octet-stream.
  • No automatic cache invalidation. Redeployed files need a cache purge (fastly service purge --all) or TTL expiry to take effect. The deploy script prints a reminder.
  • Private dictionaries are not encrypted. They prevent API enumeration but are stored in plain text. Compute services can use Secret Stores for encryption.
  • Single storage region. Object Storage is regional. Shielding ensures only one POP talks to the origin, but the data itself lives in one region. Multi-region would need multiple buckets with replication.
  • curl ≥ 7.75 required. Older systems may need the AWS CLI or another S3-compatible tool.
